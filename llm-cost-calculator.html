Assumptions behind the token counts
  • Query = one ReAct agent loop on the reasoning model: typically 4–6 LLM steps, ~35k tokens in / ~3.5k out cumulative (history grows each step; tool output is capped at 10k chars per step). Heavy = ~8–10 steps with corrective re-calls (~90k/9k).
  • Workflow creation = plan loop (~80k/15k) + execute loop that builds all widgets in one run (~200k/40k, hard step-cap 60, token ceiling 400k) + one consolidation call (~20k/5k) + naming on the fast tier. It is intentionally the expensive step — it happens once.
  • Workflow run = the frozen consolidated script replays with no per-widget LLM; the rerun agent spends ~2–4 steps to execute, verify and finalize (~15k/3k). Heavy = schema-drift repair, up to 30 steps (~250k/50k) — the adaptation is then cached.
  • PDF: ingest = Mistral OCR per page + ~10% low-confidence pages re-OCR'd on the light vision tier + a page-retrieval index (1 fast call per 8 pages, docs ≥ 10 pages). Query/run add ~1 reasoning-model extraction call per ~12 pages of document text (~7.5k in / 3k out each, capped per document).
  • Excel: ingest is heuristic-first — an LLM structure call (fast tier, top-50 rows) fires only when heuristic confidence < 0.85; a sheet index only at ≥ 15 sheets. Query and run read the ingested tables via DuckDB — no extraction calls.
  • Image: converted to a 1-page PDF and OCR'd; analysis adds at most a single small vision call.
  • Vision-call token figures for page images are approximations (~1.6k in / 1.5k out per page at 200 DPI). Cached-input discounts (≈ 90% off repeated prompt prefixes) are NOT applied — real bills for the agent loops can come in meaningfully lower.
